# Next-Change “X at Y” Visual Design

## Context

GitHub issue #64 added the workout-clock reading at the upcoming interval boundary. The first implementation rendered both clocks as one string, for example `1:47 (0:00)`. Although correct, the parentheses make the compact Ridgeline metric look like diagnostic notation and give two different clocks nearly equal visual weight. GitHub issue #62 concerns resume behavior and is not changed by this work.

## Approved presentation

Keep the existing `NEXT IN` label and render one baseline-aligned row:

```text
NEXT IN
1:47 at 0:00
```

The time until the change (`X`) remains the primary metric in the existing foreground color, monospaced family, 17sp size, and medium weight. The literal `at` and workout-clock reading (`Y`) sit immediately after it on the same baseline. They use the Ridgeline green accent at a smaller size: 12sp for `at` and 14sp for `Y`, both medium weight. Spacing is deliberately compact—4dp before `at` and 3dp before `Y`—so the phrase reads naturally without looking like three columns.

The visual text never includes parentheses or the words `remaining` or `elapsed`. In countdown mode it may read `1:47 at 0:00`; in count-up mode it may read `4:43 at 16:33`. The hero timer mode supplies the correct `Y` clock exactly as it does today.

## Data and component boundaries

`NextChangeDisplay` will expose the two formatted visual values separately rather than pre-composing punctuation:

- `timeUntilText`: the dominant `X` value.
- `timerAtChangeText`: the secondary `Y` value.
- `accessibilityDescription`: the existing explicit sentence, including whether `Y` is elapsed or remaining.

`formatNextChange` retains all current arithmetic, rounding, clock-domain, and clamping behavior. It only returns the two formatted strings separately.

`MetricsPill` continues using the generic `MetricRow` for elevation, distance, heart rate, and calories. The next-change item becomes a small dedicated `NextChangeRow`, because its primary and secondary values require different typography and colors. Its inner `NextChangeValueRow` is internal solely so an instrumented Compose test can measure the real one-line layout; the semantic wrapper remains in `NextChangeRow`. This keeps special presentation out of the generic metric abstraction.

`NextChangeRow` uses the existing `LocalOverlayBackground` and `Color.legibleOn` path for the primary monospaced value. The secondary `at Y` pieces use `LegibleText` with `RidgelineTheme.accent`. The enclosing `LegibleGlassPanel` declares both foreground and accent as required accents so its adaptive scrim accounts for every over-photo text color.

## Accessibility

The whole next-change row remains one semantic node via `clearAndSetSemantics`. Screen readers continue to receive the unambiguous description already generated by `formatNextChange`, such as:

```text
Next change in 1:47; workout remaining at change 0:00
```

The shorter visual language therefore does not reduce nonvisual clarity or expose punctuation as spoken structure.

## Boundary behavior

- The final workout boundary still counts as the next change while the last interval is running, so countdown mode can deliberately show `X at 0:00`. The row disappears only after the program stops or completes, unchanged from current behavior.
- Both clocks retain the current `m:ss` / `h:mm:ss` formatter and zero clamping.
- The row must remain on one line at the current target tablet's 1340×800 landscape viewport. Representative long values `59:59 at 1:00:00` and `1:00:00 at 12:34:56` are covered by the presentation test; if space becomes constrained, typography may scale within the row, but the phrase must not wrap or truncate either clock.
- No server API, persistence, resume logic, timer-mode behavior, or treadmill control changes are in scope.
